Reconciliation & Settlement Engine

A 3-way reconciliation and financial settlement engine with ACID guarantees, idempotent retry logic and distributed audit logging, built so that money is never settled twice and every decision can be traced.

The problem

When the same transaction is recorded in more than one system, the records drift apart. Every mismatch is either lost money or a manual investigation, and naive retry logic makes it worse: a request that times out and is retried can settle the same transaction twice.

The engine had three hard requirements:

  • Correctness: a transaction is settled once, or not at all.
  • Safe retries: networks fail, so any step must be safe to run again.
  • Traceability: finance must be able to explain every number afterwards.

Architecture

Key design decisions

Settle inside a single ACID transaction

All the writes that make up one settlement commit together or roll back together, so the database can never hold a half-settled state, even if the process crashes midway.

Idempotent retry logic

Every settlement request carries a unique key. If a request is retried after a timeout, the engine recognises the key and returns the original outcome instead of posting again. Retrying is always safe.

Distributed audit logging

Each match, settlement and retry is recorded with its inputs and result, so any figure on a finance report can be traced back to the exact decision that produced it.

Outcome

Transaction discrepancies dropped by 99.4%, with every settlement protected by ACID guarantees and safe to retry.
